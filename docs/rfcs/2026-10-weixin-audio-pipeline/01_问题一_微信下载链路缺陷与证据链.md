# 问题一：微信渠道媒体下载与网络容灾缺陷复盘

> **所属层级**：平台协议适配层（发生在文件落盘前）  
> **涉及核心源码**：`gateway/platforms/weixin.py`  
> **测试环境**：腾讯云新加坡服务器（直连海外公网），对端为微信个人号 iLink 协议服务端及腾讯 CDN 节点。

---

## 一、 真实发生时序与日志证据链（Timeline & Evidence）

### 1. 故障初发：无附言文件被底层静默吞噬（18:06 - 18:13）
- **现象**：用户在微信客户端发送音频文件（MP3 / M4A）及压缩包（ZIP），微信端显示已发出，但 Hermes 对话界面完全无反应，Agent 没有任何输出。
- **系统日志现场**（提取自 `journalctl --user -u hermes-gateway.service`）：
  ```text
  Oct 15 18:06:33 VM-0-11-ubuntu hermes[371333]: 2026-10-15 18:06:33,381 WARNING gateway.platforms.weixin: [Weixin] file download failed:
  Oct 15 18:09:30 VM-0-11-ubuntu hermes[371333]: 2026-10-15 18:09:30,437 WARNING gateway.platforms.weixin: [Weixin] file download failed:
  Oct 15 18:13:22 VM-0-11-ubuntu hermes[371333]: 2026-10-15 18:13:22,149 WARNING gateway.platforms.weixin: [Weixin] file download failed:
  ```
- **证据剖析**：
  在 `gateway/platforms/weixin.py` 第 899 行：
  ```python
  if not text and not media_paths:
      return
  ```
  因为用户只发送了文件而没有附带文本，`text` 为空；同时下载逻辑抛出异常被 `except` 捕获返回 `None`，导致 `media_paths` 也为空。网关直接无声无息地执行了 `return`。**这是典型的“静默吞噬”高危 Bug**。

## 二、 微信渠道的 6 大技术根因深度剖析

### 1. 媒体下载链接优先级倒置（Priority Inversion）
- **原版错误代码**：
  ```python
  if encrypted_query_param:
      url = f"{cdn_base_url.rstrip('/')}/download?encrypted_query_param={quote(encrypted_query_param, safe='')}"
  elif full_url:
      _assert_weixin_cdn_url(full_url)
      url = full_url
  ```
- **机理分析**：微信服务在推送媒体事件时，会提供服务端就近计算分配的动态直连地址 `full_url`（带预签名和地域就近路由）。原代码优先判断 `encrypted_query_param` 并拼接写死的 `novac2c` 域名，导致新加坡海外节点直接被打到国内电信节点，绕开了腾讯海外就近 CDN 加速。
- **修复方案**：`if full_url: url = full_url` 置顶。

### 2. SSRF 域名白名单静态写死
- **机理分析**：`_WEIXIN_CDN_ALLOWLIST` 仅硬编码 7 个静态域名。微信媒体分发使用庞大的子域名分片（如 `*.cdn.weixin.qq.com`、`*.qpic.cn`），静态匹配会误伤合法下载。
- **修复方案**：改用泛域名后缀校验 `host.endswith((".weixin.qq.com", ".qpic.cn", ".qlogo.cn"))`。

### 3. 单文件下载超时硬编码 60 秒
- **机理分析**：`_INBOUND_MEDIA[ITEM_FILE]` 字典中对普通文件的超时硬编码为 `60.0` 秒。跨国网络下拉取几十兆的音频、视频或压缩包极易超限。
- **修复方案**：将 `ITEM_FILE` 默认超时调整至 `180.0` 秒。

### 4. 异步事件循环与流式阻塞
- **机理分析**：复用长轮询的 `_poll_session` 下载大二进制文件，长轮询心跳与大文件单缓冲读取发生连接池资源竞争，在 `aiohttp.streams.readany()` 陷入死锁。
- **修复方案**：使用独立线程传输流进行二进制下载，支持自适应滑动窗口与分块缓冲。

### 5. 静默丢弃无附言附件
- **机理分析**：无文本附言且媒体下载抛异常时直接 `return`，完全抹杀事件。
- **修复方案**：捕获异常时注入占位符 `[附件下载失败：微信传输超时或CDN解析错误]`，激活通知。

### 6. 内存临时凭据随异常丢弃
- **机理分析**：微信报文内的动态 AES-128 密钥在内存异常时随垃圾回收被销毁，而 `sync_buf` 已推进，导致无法进行后台断点补拉。
- **修复方案**：在进入网络下载前，先原子落盘至 `cache/last_inbound_media.json` 留痕固化。
